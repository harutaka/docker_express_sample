# バージョン情報取得API設計

## 日時
2025年10月9日 18:01

## 背景
連携しているWebアプリから現在稼働中のWebアプリのバージョンを知りたいという要請がある。
バージョン互換性の確認やデバッグのため、APIを通じてアプリケーションバージョンを取得できるようにする必要がある。

## 決定事項

### エンドポイント
- **パス**: `GET /version`
- **レスポンス形式**: JSON
- **ステータスコード**: 200 OK

### レスポンス構造
```json
{
  "version": "0.0.4"
}
```

### バージョン情報の取得方法
`package.json`のバージョン情報を動的に読み込む方法を採用する。

**理由**:
- `package.json`が唯一の信頼できる情報源（Single Source of Truth）
- ビルド時やデプロイ時のバージョン更新漏れを防げる
- メンテナンスコストが低い

## 実装計画

### 1. ハンドラーの追加
**ファイル**: `src/handlers/base.ts`

`package.json`からバージョンを読み込み、JSONで返すハンドラー関数 `getVersion` を追加する。

実装のポイント:
- TypeScriptのimport assertionsを使用して`package.json`を読み込む
- エラーハンドリングを適切に行う

### 2. ルート定義の追加
**ファイル**: `src/routes/base.ts`

`GET /version`のルートを定義し、`getVersion`ハンドラーと紐付ける。

### 3. テストの追加（オプション）
**ファイル**: `tests/`以下（実装後に必要に応じて）

- `/version`エンドポイントが200を返すことを確認
- レスポンスに`version`フィールドが含まれることを確認
- バージョンが`package.json`と一致することを確認

## 代替案と不採用理由

### 環境変数からバージョンを取得
**不採用理由**:
- デプロイ時に環境変数の設定が必要で運用コストが高い
- 設定漏れのリスクがある

### ビルド時に定数ファイルを生成
**不採用理由**:
- ビルドプロセスが複雑になる
- 開発環境と本番環境で挙動が変わる可能性がある

## 影響範囲
- 新規エンドポイントの追加のみ
- 既存機能への影響なし
- 破壊的変更なし

## セキュリティ考慮事項
- バージョン情報は公開情報として扱う
- 認証・認可は不要と判断（ヘルスチェック系エンドポイントと同様）
- 機密情報を含まない
